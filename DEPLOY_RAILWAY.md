# Деплой на Railway

GitHub → Railway: кожен пуш у гілку автоматично перевикочує бота.
Репозиторій містить `railway.json` (команда старту) і `.python-version`
(версія Python). Решту Railway визначає сам за `requirements.txt`.

Білдер у `railway.json` навмисно не вказаний: Railway використовує свій
поточний (Railpack), який коректно ставить Python і залежності. Не
прописуйте `"builder": "NIXPACKS"` — стара збірка падає з
`No module named pip`.

---

## ⚠ Найголовніше: том для бази

Файлова система контейнера на Railway **ефемерна** — вона стирається при
кожному деплої, рестарті й переїзді на інший сервер. Без тому ви втратите
всі заявки, сесії анкет і листування з клієнтами після першого ж пушу
в GitHub.

**Обов'язково:**
1. Railway → ваш сервіс → **Settings → Volumes → Add Volume**.
2. **Mount path:** `/data`, розмір 1 GB (вистачить надовго: заявка ≈ 2 КБ).

Більше нічого робити не треба — застосунок сам побачить змінну
`RAILWAY_VOLUME_MOUNT_PATH` і покладе базу в `/data/delivery.sqlite3`.

Якщо том не прикріплено, бот при старті напише помилку в лог **і надішле
попередження всім менеджерам у Telegram** — щоб проблему не проґавили.

## Крок за кроком

### 1. Створити проєкт
Railway → **New Project → Deploy from GitHub repo** →
обрати `cyfrovahata-bit/bot_rozrahunok_dorogy` → гілку з кодом.

### 2. Додати том
Див. розділ вище. Зробіть це **до** першого бойового запуску.

### 3. Змінні оточення
Railway → **Variables**. Файл `.env` у контейнер не потрапляє
(він у `.gitignore`), тому змінні задаються тут:

| Змінна | Значення | Обов'язково |
|--------|----------|-------------|
| `TELEGRAM_BOT_TOKEN` | токен від @BotFather | так |
| `MANAGER_CHAT_IDS` | `123456789,987654321` | так |
| `GEO_PROVIDER` | `google` | так |
| `GOOGLE_MAPS_API_KEY` | ключ Google Cloud | так |
| `GEO_FALLBACK` | `offline` | бажано |
| `ORDERS_CHAT_ID` | чат, куди дублювати всі заявки | ні |
| `WORK_HOURS_START` / `WORK_HOURS_END` | `9` / `19` | ні |
| `DB_PATH` | **не задавайте** — підставиться `/data/delivery.sqlite3` | ні |

### 4. Деплой
Railway збере проєкт сам.

**Перший деплой без токена падає — це нормально.** У логах буде:
```
TELEGRAM_BOT_TOKEN не заданий. Створіть бота у @BotFather...
```
Контейнер перезапуститься 10 разів (політика з `railway.json`) і зупиниться
зі статусом CRASHED. Щойно додасте `TELEGRAM_BOT_TOKEN` у Variables, Railway
перезапустить сервіс сам, і в логах з'явиться:
```
Бот @your_bot запущено. Менеджери: (123456789,)
```

Перевірено на цьому проєкті: збірка проходить, том монтується в `/data`,
змінні читаються з панелі Railway.

## Що варто знати про цю конфігурацію

**Домен і порт не потрібні.** Бот працює через long polling — сам ходить
до Telegram. HTTP-порт не відкривається, тому не вмикайте healthcheck і не
генеруйте домен: Railway вважатиме сервіс несправним і перезапускатиме його
по колу.

**Тільки одна репліка.** У `railway.json` стоїть `numReplicas: 1`, і міняти
це не можна: два контейнери одночасно не можуть читати одну чергу Telegram
(помилка `Conflict: terminated by other getUpdates request`). Масштабувати
бота реплікаціями не вийде — лише переходом на webhook.

**Під час деплою ~30 секунд працюють два контейнери** (Railway піднімає
новий перед зупинкою старого). Старий отримає від Telegram помилку конфлікту
і завершиться — це нормально, повідомлення не губляться. При зупинці бот
коректно закриває сесію, щоб Telegram швидше віддав чергу новому контейнеру.

**Тарифи оновлюються без деплою.** У боті команда `/reload` перечитує
`config/tariffs.yaml`. Але сам файл лежить у репозиторії, тож зміна цін —
це коміт у GitHub (він і запустить деплой). Якщо хочете міняти ціни без
пушу — скажіть, винесу тарифи в змінні оточення або в адмінку.

## Резервне копіювання

База — один файл на томі. Раз на тиждень варто робити копію:

```bash
railway ssh                                  # зайти в контейнер
sqlite3 /data/delivery.sqlite3 ".backup /data/backup-$(date +%F).sqlite3"
```

Або вивантажити заявки через бота командою `/orders`.

Коли заявок стане більше кількох тисяч на місяць — час переходити на
PostgreSQL (Railway додає його в один клік). Тоді змінюється лише
`delivery/storage/repo.py`, решта коду не чіпається.

## Якщо бот не піднявся

| Симптом у логах | Причина | Що робити |
|-----------------|---------|-----------|
| `TELEGRAM_BOT_TOKEN не заданий` | немає змінної | додати у Variables |
| `Unauthorized` | токен зіпсований | перевірити токен у @BotFather |
| `Conflict: terminated by other getUpdates` | два контейнери або бот запущений локально | лишити одну репліку, зупинити локальний запуск |
| `На Railway не прикріплено Volume` | немає тому | Settings → Volumes → `/data` |
| `GOOGLE_MAPS_API_KEY порожній` | немає ключа | додати ключ; поки що кілометраж рахується приблизно |
| `ModuleNotFoundError: aiogram` | збірка не побачила requirements.txt | перевірити, що файл у корені репозиторію |
