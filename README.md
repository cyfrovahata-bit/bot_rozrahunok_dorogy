# Розрахунок вартості доставки

Застосунок приймає заявку через **5 блоків питань**, сам визначає **кілометраж**,
рахує **вартість за коефіцієнтами** і за потреби **підключає менеджера до розмови**.

Ядро не залежить від Telegram — бот, HTTP API і консоль це лише оболонки
над однією й тією ж логікою. Тому підключення до Telegram зводиться до
вписування токена, а не до переписування розрахунку.

```
   Telegram-бот ─┐
   HTTP API ─────┼──► OrderService ──► анкета → кілометраж → ціна → заявка
   Консоль ──────┘         │
                           └────────► ManagerService ──► менеджер у чаті
```

---

## Швидкий старт (працює вже зараз, без ключів і без інтернету)

```bash
pip install PyYAML                    # єдина залежність ядра
python -m delivery.cli --demo         # прогнати приклад заявки
python -m delivery.cli                # пройти анкету вручну
python -m delivery.cli --distance Київ Львів
python -m delivery.cli --orders       # останні заявки
python -m unittest discover tests     # 73 тести
```

## 5 блоків питань

| # | Блок | Що питаємо |
|---|------|------------|
| 1 | Клієнт | ім'я, телефон, фіз/юр особа, назва компанії |
| 2 | Маршрут | місто й адреса завантаження і розвантаження, додаткові точки, зворотний рейс |
| 3 | Вантаж | тип, вага, об'єм, кількість місць, оголошена вартість |
| 4 | Транспорт і послуги | тип авто, температурний режим, вантажники, гідроборт, терміновість |
| 5 | Дата й оплата | дата подачі, спосіб оплати, ПДВ, страхування, коментар, виклик менеджера |

Питання описані в `config/questions.yaml` — тексти, варіанти й порядок
змінюються **без правок коду**. Підтримувані типи: `text`, `address`, `phone`,
`email`, `number`, `int`, `bool`, `choice`, `multichoice`, `date`.
Питання можна показувати за умовою (`depends_on`) — напр. «Назва компанії»
з'являється лише юрособам.

## Як рахується ціна

`config/tariffs.yaml`, порядок нарахування:

1. **Подача авто** — фікс.
2. **Кілометраж** — прогресивний тариф: перші 50 км по 26 грн, далі 200 км по 22, і т.д.
3. **Коефіцієнти** (множники): тип авто × тип вантажу × терміновість × температурний режим × вихідний день.
4. **Перевищення вантажопідйомності** — % за кожну почату тонну понад ліміт авто.
5. **Послуги** — вантажники, гідроборт, додаткові точки, зворотний рейс.
6. **Страхування** — % від оголошеної вартості (не менше мінімуму).
7. **Паливний збір** — % від проміжної суми, потім знижка.
8. **Мінімальна вартість** замовлення, округлення, **ПДВ**.

Клієнт бачить не лише цифру, а всю деталізацію — кожен крок окремим рядком:

```
• Подача авто: +350 грн
• Перевезення 552 км: +10 776 грн  (50 км × 26; 150 км × 22; 300 км × 18; 52 км × 15)
• Тип транспорту: +3 894 грн  (×1.35)
• Тип вантажу: +2 253 грн  (×1.15)
• Вантажники: +900 грн  (2 × 450)
• ПДВ 20%: +4 740 грн
РАЗОМ: 28 440 грн
```

### Зміна тарифів
Правите `config/tariffs.yaml` → **обов'язково** `python -m unittest discover tests`
(тест `test_config_consistency` ловить розсинхрон між анкетою і тарифами) →
у боті команда `/reload` перечитує тарифи без перезапуску.

## Визначення кілометражу

Три режими, перемикаються змінною `GEO_PROVIDER` у `.env`:

| Режим | Точність | Що потрібно | Коли використовувати |
|-------|----------|-------------|----------------------|
| `offline` | похибка 1–10% | нічого | тест, розробка, резерв |
| `osm` | реальні дороги | інтернет; ліміт ~1 запит/сек | малий потік заявок |
| `google` | найточніше, з заторами | API-ключ + платіжна картка | **обрано для продакшну** |

За замовчуванням у `.env.example` стоїть `google` з резервом `offline`: поки ключ не
вписаний, застосунок не падає, а працює на офлайн-оцінці й пише попередження в лог.

Якщо основний сервіс недоступний — автоматично спрацьовує `GEO_FALLBACK`,
клієнт отримує оцінку з поміткою «уточнить менеджер». Усі маршрути
кешуються в SQLite, тому повторні запити безкоштовні й миттєві.

## Підключення менеджера до бесіди

1. Клієнт натискає «Підключити менеджера» (або так відповідає в 5-му блоці,
   або розрахунок не вдався — тоді автоматично).
2. Усім менеджерам з `MANAGER_CHAT_IDS` прилітає картка заявки з кнопкою «Взяти в роботу».
3. Перший, хто натиснув, стає співрозмовником; решта бачать «заявку вже взято»
   (захист від подвійного взяття перевірено тестом).
4. Повідомлення ретранслюються в обидва боки, листування зберігається в БД.
5. `/close` завершує розмову.

Поза робочим часом (`WORK_HOURS_*`) клієнт отримує чесне попередження,
коли з ним зв'яжуться, а заявка все одно лягає в чергу.

## Підключення Telegram-бота

```bash
pip install aiogram
cp .env.example .env        # вписати TELEGRAM_BOT_TOKEN і MANAGER_CHAT_IDS
python -m delivery.bot.telegram
```

Команди клієнта: `/start`, `/restart`, `/manager`, `/help`
Команди менеджера: `/queue`, `/take <id>`, `/close`, `/orders`, `/stats`, `/reload`

## HTTP API (для сайту або CRM)

```bash
pip install fastapi "uvicorn[standard]"
python -m delivery.api.app     # документація: http://localhost:8000/docs
```

`POST /api/sessions` → `POST /api/sessions/{id}/answer` → `POST /api/sessions/{id}/quote`,
а також разовий `POST /api/quote` і `GET /api/distance?from=Київ&to=Львів`.

## Деплой на Railway

Репозиторій готовий до автодеплою: `railway.json` + `nixpacks.toml`,
кожен пуш у GitHub перевикочує бота.

**Обов'язково прикріпіть Volume на `/data`** — інакше файлова система
контейнера стирається при кожному деплої разом з усіма заявками.
Застосунок сам покладе базу на том і, якщо тому немає, попередить про це
в логах і повідомленням менеджерам.

Змінні задаються в панелі Railway (файл `.env` у контейнер не потрапляє).
Порт і домен не потрібні: бот працює через long polling, репліка лише одна.

Повна інструкція, включно з відновленням після збоїв — `DEPLOY_RAILWAY.md`.

## Структура

```
railway.json              конфігурація деплою
nixpacks.toml             збірка контейнера
config/questions.yaml     5 блоків питань
config/tariffs.yaml       тарифи й коефіцієнти
delivery/
  questionnaire/          схема питань, валідація, рушій проходження
  geo/                    кілометраж: offline / OSM / Google + кеш
  pricing/                тарифи й калькулятор
  storage/                SQLite: сесії, заявки, розмови
  services/               OrderService, ManagerService, мапінг анкета→калькулятор
  bot/telegram.py         Telegram (aiogram) — опційно
  api/app.py              HTTP API (FastAPI) — опційно
  cli.py                  консольний режим
tests/                    73 тести
```
